# split-check-bot

Telegram-бот для компании друзей, который поможет разделить общий чек после
ресторана или кафе. Команда `/start` открывает приветствие и inline-меню:
разделить чек, мои компании и краткая инструкция.
Кнопка разделения чека предлагает фотографию или ручной ввод.
Ручной ввод позволяет добавить позиции и увидеть общую сумму.
По умолчанию фотографии распознаются локально через PaddleOCR без API-ключа
и платных запросов. Позиции и суммы показываются для проверки и сохраняются
в текущий чек только после подтверждения.
Распределение расходов между участниками, сохранение компаний и платежи
пока не реализованы.

Используются Python 3.12, aiogram 3.x, PaddleOCR 3.7, PaddlePaddle CPU 3.2.2,
python-dotenv и Pydantic. GPU не требуется. Бот работает асинхронно
и получает сообщения через long polling.

## Локальный запуск

1. Установите Python 3.12 и откройте терминал в корне проекта.
2. Создайте виртуальное окружение:

   ```bash
   python3.12 -m venv .venv
   ```

   На Windows можно использовать `py -3.12 -m venv .venv`.

3. Активируйте окружение:

   ```bash
   source .venv/bin/activate
   ```

   В Windows PowerShell: `.venv\Scripts\Activate.ps1`.

4. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

5. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram командой
   `/newbot` и получите токен.
6. Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

   В Windows PowerShell: `Copy-Item .env.example .env`.
   Откройте `.env` и заполните `BOT_TOKEN` токеном от BotFather:

   ```dotenv
   BOT_TOKEN=ваш_токен_от_BotFather
   ```

   `.env` исключён из Git. Не публикуйте токен и не добавляйте его в исходный код.
   Если `BOT_TOKEN` уже задан в окружении, он имеет приоритет над `.env`.

7. Запустите бота из корня проекта:

   ```bash
   python -m bot
   ```

8. Откройте своего бота в Telegram и отправьте `/start`. Он должен ответить:

   ```text
   Привет! 👋
   Я помогу разделить общий чек между друзьями.

   Что хотите сделать?
   ```

   Под приветствием появятся кнопки «🧾 Разделить чек», «👥 Мои компании»
   и «ℹ️ Как это работает». В разделе чека доступна кнопка «✍️ Ввести вручную».

Для остановки нажмите `Ctrl+C`. Для работы нужен доступ к `api.telegram.org`.
Запускайте только один экземпляр long polling с одним токеном; у бота не должен
быть активен webhook.

## Распознавание фотографии чека

Основной backend — локальный `PaddleOCR`; `OPENAI_API_KEY` ему не нужен.
Установка CPU-зависимостей выполняется обычной командой:

```bash
python -m pip install -r requirements.txt
python -m bot.services.paddle_receipt_recognition
```

Вторая команда заранее загружает и инициализирует веса OCR без обработки
пользовательских фотографий. На первом запуске нужен доступ к официальному
серверу моделей `paddle-model-ecology.bj.bcebos.com` (HTTPS). После загрузки
весов OCR работает без сети; бот использует только Telegram API.
В управляемой среде разрешите домен моделей в сетевой политике, затем повторите
команду подготовки. Если загрузка блокируется, это не исправляется API-ключом.

Используются `PP-OCRv5_mobile_det` и `cyrillic_PP-OCRv5_mobile_rec` на CPU.
Кириллическая модель поддерживает русский текст, цифры и латинские буквы
(включая английские названия). См. [официальную документацию PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/OCR.en.md)
и [словарь модели](https://github.com/PaddlePaddle/PaddleOCR/blob/main/ppocr/utils/dict/ppocrv5_cyrillic_dict.txt).
Поворот по EXIF учитывается; страницу лучше фотографировать целиком и ровно,
так как дополнительные модели выравнивания и ориентации отключены.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Существующий токен Telegram-бота |
| `RECEIPT_OCR_BACKEND` | `paddleocr` по умолчанию; опционально `openai` |
| `PADDLE_DET_MODEL_DIR` | Необязательно: каталог локальной модели детекции |
| `PADDLE_REC_MODEL_DIR` | Необязательно: каталог локальной кириллической модели |
| `OCR_CACHE_DIR` | Кеш моделей; по умолчанию `work/ocr-cache`, исключённый из Git |

Для полностью автономной установки заранее скачайте официальные веса
в окружении с доступом к серверу моделей и укажите два локальных каталога
через `PADDLE_DET_MODEL_DIR` и `PADDLE_REC_MODEL_DIR`. Они должны содержать
распакованные inference-модели, включая конфигурацию и файлы весов.
Системные CA и прокси сохраняются, проверка TLS включена.

Нажмите «🧾 Разделить чек» и отправьте Telegram-фотографию. Бот ответит:
«Чек получен 🧾\nРаспознаю текст…». Изображение скачивается в память
(`BytesIO`), проверяется и передаётся PaddleOCR. Допускаются файлы до 10 МиБ
и изображения до 25 мегапикселей; для CPU они уменьшаются до 2400 пикселей
по длинной стороне. Один экземпляр движка работает в отдельном потоке,
поэтому CPU-распознавание не блокирует event loop Telegram-бота.

Парсер нормализует пробелы и объединяет ячейки одной строки по координатам.
Поддерживаются названия с суммой справа, количество × цена, колонки
количество/цена/сумма и названия на строке перед ценой. Денежные значения
разбираются через `Decimal`; точка, запятая и пробелы тысяч поддерживаются.
Служебные строки (ИНН, касса, чек, QR, фискальные номера, дата/время, оплата,
НДС, скидки) отфильтровываются. «ИТОГО» извлекается отдельно, а не как товар.
Если виден только итог позиции, количество предварительно считается равным
одному, а неизвестная цена за единицу остаётся `null`. Валюта по умолчанию RUB;
явные обозначения USD/EUR учитываются.

Это эвристическое распознавание: необычная вёрстка, скидки и ошибки символов
могут дать неполный или неверный список. Бот всегда предлагает проверить
позиции. Показываются сумма найденных позиций и итог чека, если он найден;
при расхождении появляется предупреждение о возможной ошибке OCR.
Пустой/нечитаемый результат предлагает новую фотографию или ручной ввод.
Распознанный текст, фото и base64 не выводятся в лог и не сохраняются на диск.
В кеше хранятся только общие веса моделей, а не пользовательские фото.

Кнопки проверки сохранены:

- «✅ Всё верно» — переносит позиции в текущий чек пользователя в FSM;
- «✏️ Исправить» — сообщает, что редактирование появится позже;
- «🔄 Распознать заново» — повторно скачивает последнюю фотографию и выполняет OCR;
- «❌ Отменить» — очищает состояние и возвращает стартовое меню.

Фото вне сценария получает подсказку с кнопкой начала разделения чека.
Во время ручного ввода фотография не сбрасывает шаг и добавленные позиции.
Файл и массив пикселей существуют только на время обработки; в FSM остаются
результат для проверки и метаданные Telegram. При подтверждении метаданные
фото удаляются. Новый чек, ручной ввод, отмена, `/start` и перезапуск очищают
соответствующие временные данные. База данных не используется.

### Опциональный OpenAI backend

Старая интеграция сохранена отдельно в `openai_receipt_recognition.py`.
Она не импортируется и не вызывается при стандартном локальном сценарии.
Автоматического перехода к платному API при ошибке PaddleOCR нет.

Для будущего явно выбранного облачного режима нужно отдельно установить
`requirements-openai.txt`, задать `RECEIPT_OCR_BACKEND=openai`,
`OPENAI_API_KEY` в секретах и при необходимости `OPENAI_MODEL`
(по умолчанию `gpt-4.1-mini`). Этот режим использует платный Responses API
и требует разрешённого `api.openai.com`; для локального OCR всё это не нужно.
Никогда не добавляйте настоящие ключи в репозиторий; `.env` исключён из Git.

## Ручной ввод чека

Нажмите «🧾 Разделить чек» → «✍️ Ввести вручную». Бот последовательно спросит
название позиции, цену в рублях и количество. Цена должна быть больше нуля;
поддерживаются целые числа и дробные числа с точкой или запятой.
Количество — целое число больше нуля. При ошибке бот повторяет текущий шаг.

После добавления бот показывает список позиций, стоимость каждой позиции
(цена × количество) и общую сумму. «➕ Добавить позицию» запускает следующий
ввод, «✅ Закончить ввод» показывает итог и завершает сценарий,
«❌ Отменить» очищает чек и возвращает стартовое меню. `/start` также сбрасывает
текущий ввод. Расчёты используют `Decimal` без ошибок округления `float`.

Чеки и состояние FSM хранятся только в оперативной памяти отдельно для каждого
пользователя и чата. После завершения ручного ввода, отмены или перезапуска
бота они очищаются. Подтверждённый распознанный чек остаётся до нового чека,
отмены, `/start` или перезапуска.
База данных не используется.

## Структура

```text
bot/
    __init__.py     # Пакет приложения
    __main__.py     # Запуск бота и подключение обработчиков
    config.py       # Загрузка BOT_TOKEN из окружения и .env
    handlers.py     # Стартовое меню и обработчики callback-кнопок
    receipt.py      # Проверка цены/количества и форматирование сумм чека
    services/
        __init__.py
        receipt_recognition.py # Выбор backend, PaddleOCR по умолчанию
        receipt_models.py      # Общие модели позиций и ошибки
        paddle_receipt_recognition.py # CPU OCR и группировка строк
        receipt_parser.py      # Эвристики выделения позиций и итогов
        openai_receipt_recognition.py # Опциональная облачная интеграция
tests/
    test_config.py  # Проверки загрузки токена
    test_handlers.py # Telegram-сценарии, FSM и кнопки через диспетчер aiogram
    test_receipt_recognition.py # Опциональный OpenAI SDK без платных запросов
    test_paddle_receipt_recognition.py # Локальный backend и парсер строк
.env.example       # Шаблон настроек без настоящего токена
.python-version    # Версия Python для инструментов разработки
requirements.txt   # Основные зависимости приложения и PaddleOCR CPU
requirements-openai.txt # Опциональные зависимости OpenAI
```

## Тесты

После установки зависимостей выполните из корня проекта:

```bash
python -m unittest discover -s tests -v
```

Тесты используют стандартный `unittest`: проверяют загрузку настроек и отправку
приветствия и inline-меню в ответ на `/start`, ответов callback-кнопок,
полного FSM-сценария, ошибок ввода, отмены и изоляции чеков пользователей.
Также проверяются фото внутри и вне сценария, переход к ручному вводу,
отмена после фото и сохранение текущего ручного ввода при получении изображения.
Проверки локального OCR включают группировку колонок, русский и английский
текст, фильтрацию фискальных строк, дробное количество, точность сумм,
нечитаемый результат, отсутствие необходимости в API-ключе и отказ от
автоматического облачного fallback. Движок подменяется, поэтому для обычного
запуска тестов веса моделей не скачиваются. Декодирование изображения
проверяется настоящими Pillow/NumPy с подменённым OCR-движком.

Проверки опционального облачного режима включают несколько позиций, количество больше единицы,
точность сумм, расхождение итогов, пустой/нечитаемый ответ, ошибку API, отсутствие
ключа, подтверждение и повтор. Telegram и OpenAI подменяются: используется fake
клиент, а контракт настоящего OpenAI SDK проверяется через `httpx.MockTransport`.
Платных запросов нет; настоящие токены и доступ к сети для тестов не нужны.
При отсутствии опционального OpenAI SDK его тесты пропускаются.
