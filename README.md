# split-check-bot

Telegram-бот для компании друзей, который поможет разделить общий чек после
ресторана или кафе. Команда `/start` открывает приветствие и inline-меню:
разделить чек, мои компании и краткая инструкция.
Кнопка разделения чека предлагает фотографию или ручной ввод.
Ручной ввод позволяет добавить позиции и увидеть общую сумму.
Фотографии распознаются через OpenAI Responses API: позиции и суммы показываются
для проверки и сохраняются в текущий чек только после подтверждения.
Распределение расходов между участниками, сохранение компаний и платежи
пока не реализованы.

Используются Python 3.12, aiogram 3.x, python-dotenv, OpenAI SDK и Pydantic. Бот работает асинхронно
и получает сообщения через long polling.

## Локальный запуск

1. Установите Python 3.12 и откройте терминал в корне проекта.
2. Создайте виртуальное окружение:

   ```bash
   python3.12 -m venv .venv
   ```

   На Windows можно использовать `py -3.12 -m venv .venv`.

3. Активируйте окружение:

   ```bash
   source .venv/bin/activate
   ```

   В Windows PowerShell: `.venv\Scripts\Activate.ps1`.

4. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

5. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram командой
   `/newbot` и получите токен.
6. Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

   В Windows PowerShell: `Copy-Item .env.example .env`.
   Откройте `.env` и заполните `BOT_TOKEN` токеном от BotFather:

   ```dotenv
   BOT_TOKEN=ваш_токен_от_BotFather
   ```

   `.env` исключён из Git. Не публикуйте токен и не добавляйте его в исходный код.
   Если `BOT_TOKEN` уже задан в окружении, он имеет приоритет над `.env`.

7. Запустите бота из корня проекта:

   ```bash
   python -m bot
   ```

8. Откройте своего бота в Telegram и отправьте `/start`. Он должен ответить:

   ```text
   Привет! 👋
   Я помогу разделить общий чек между друзьями.

   Что хотите сделать?
   ```

   Под приветствием появятся кнопки «🧾 Разделить чек», «👥 Мои компании»
   и «ℹ️ Как это работает». В разделе чека доступна кнопка «✍️ Ввести вручную».

Для остановки нажмите `Ctrl+C`. Для работы нужен доступ к `api.telegram.org`.
Запускайте только один экземпляр long polling с одним токеном; у бота не должен
быть активен webhook.

## Распознавание фотографии чека

Для распознавания задайте `OPENAI_API_KEY` через переменные окружения
(в облачной среде — секрет, привязанный к переменной с этим именем).
Никогда не добавляйте настоящий ключ в репозиторий; `.env` исключён из Git.
Для локальной работы можно заполнить переменные из `.env.example` в своём `.env`.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Существующий токен Telegram-бота |
| `OPENAI_API_KEY` | Ключ OpenAI; без него ручной ввод продолжает работать |
| `OPENAI_MODEL` | Необязательно; по умолчанию `gpt-4.1-mini` |

Выбранная модель должна поддерживать изображения, Responses API и Structured
Outputs (JSON Schema). Сетевой доступ нужен к `api.telegram.org` и `api.openai.com`.
В управляемой среде добавьте `api.openai.com` в список разрешённых доменов,
а секрет OpenAI привяжите к этому домену. Прокси и системные CA сохраняются,
проверка TLS включена. После добавления секрета перезапустите бота.

Нажмите «🧾 Разделить чек» и отправьте фото обычным Telegram-сообщением типа
`photo`. Бот скачивает наибольший вариант из `Message.photo` в `BytesIO` и
отправляет изображение в OpenAI. Обрабатываются фотографии до 10 МиБ.
Сервис вызывает `responses.parse` с Pydantic-моделью и `store=False`.
Произвольный OCR-текст не разбирается: модель возвращает структурированные
позиции (`name`, `quantity`, `unit_price`, `total_price`), итог чека и валюту.
Количество и денежные значения в JSON передаются десятичными строками;
суммы считаются через `Decimal`. Неопределимая цена за единицу остаётся `null`.
Взвешенные товары могут иметь дробное количество.

Бот показывает позиции, сумму по позициям и итог чека. При расхождении сумм
выводится предупреждение. Неизвестные валюта или итог явно отмечаются.
Доступны кнопки:

- «✅ Всё верно» — переносит позиции в текущий чек пользователя в FSM;
- «✏️ Исправить» — пока сообщает, что редактирование появится позже;
- «🔄 Распознать заново» — повторно скачивает последнюю фотографию и распознаёт её;
- «❌ Отменить» — очищает состояние и возвращает стартовое меню.

При нечитаемом чеке, пустом ответе, отказе модели или ошибке API бот предлагает
новую фотографию, ручной ввод или отмену. Без `OPENAI_API_KEY` он сообщает,
что распознавание пока не настроено; запрос к OpenAI не выполняется.
Фото вне сценария получает подсказку с кнопкой начала разделения чека.
Во время ручного ввода фотография не сбрасывает шаг и добавленные позиции.

Изображения и base64 находятся только в памяти на время запроса, на диск
не записываются и в лог не попадают. `BytesIO` закрывается и при ошибке.
В FSM до подтверждения остаются только Telegram-метаданные фото и результат
для проверки; повтор использует `file_id`, а не сохранённые байты изображения.
При подтверждении метаданные фото удаляются, позиции остаются в памяти FSM.
Новый чек, ручной ввод, отмена, `/start` или перезапуск очищают соответствующие
временные данные. Ключи и тела API-запросов не логируются; при ошибке сервиса
в лог попадают только её тип и HTTP-статус, если доступен.
База данных и постоянное хранение фото не используются.

## Ручной ввод чека

Нажмите «🧾 Разделить чек» → «✍️ Ввести вручную». Бот последовательно спросит
название позиции, цену в рублях и количество. Цена должна быть больше нуля;
поддерживаются целые числа и дробные числа с точкой или запятой.
Количество — целое число больше нуля. При ошибке бот повторяет текущий шаг.

После добавления бот показывает список позиций, стоимость каждой позиции
(цена × количество) и общую сумму. «➕ Добавить позицию» запускает следующий
ввод, «✅ Закончить ввод» показывает итог и завершает сценарий,
«❌ Отменить» очищает чек и возвращает стартовое меню. `/start` также сбрасывает
текущий ввод. Расчёты используют `Decimal` без ошибок округления `float`.

Чеки и состояние FSM хранятся только в оперативной памяти отдельно для каждого
пользователя и чата. После завершения ручного ввода, отмены или перезапуска
бота они очищаются. Подтверждённый распознанный чек остаётся до нового чека,
отмены, `/start` или перезапуска.
База данных не используется.

## Структура

```text
bot/
    __init__.py     # Пакет приложения
    __main__.py     # Запуск бота и подключение обработчиков
    config.py       # Загрузка BOT_TOKEN из окружения и .env
    handlers.py     # Стартовое меню и обработчики callback-кнопок
    receipt.py      # Проверка цены/количества и форматирование сумм чека
    services/
        __init__.py
        receipt_recognition.py # Responses API, модели результата и ошибки
tests/
    test_config.py  # Проверки загрузки токена
    test_handlers.py # Telegram-сценарии, FSM и кнопки через диспетчер aiogram
    test_receipt_recognition.py # Сервис и контракт SDK без платных запросов
.env.example       # Шаблон настроек без настоящего токена
.python-version    # Версия Python для инструментов разработки
requirements.txt   # Зависимости приложения
```

## Тесты

После установки зависимостей выполните из корня проекта:

```bash
python -m unittest discover -s tests -v
```

Тесты используют стандартный `unittest`: проверяют загрузку настроек и отправку
приветствия и inline-меню в ответ на `/start`, ответов callback-кнопок,
полного FSM-сценария, ошибок ввода, отмены и изоляции чеков пользователей.
Также проверяются фото внутри и вне сценария, переход к ручному вводу,
отмена после фото и сохранение текущего ручного ввода при получении изображения.
Проверки распознавания включают несколько позиций, количество больше единицы,
точность сумм, расхождение итогов, пустой/нечитаемый ответ, ошибку API, отсутствие
ключа, подтверждение и повтор. Telegram и OpenAI подменяются: используется fake
клиент, а контракт настоящего OpenAI SDK проверяется через `httpx.MockTransport`.
Платных запросов нет; настоящие токены и доступ к сети для тестов не нужны.
