# split-check-bot

Для сравнения качества OCR на собственных чеках доступен отдельный
`python -m tests.receipt_benchmark`. Формат эталонов, безопасные примеры,
метрики и сохранение отладочных изображений описаны в
[инструкции benchmark](tests/fixtures/receipts/README.md).

Telegram-бот для разделения общего чека между друзьями. `/start` открывает меню;
«🧾 Разделить чек» предлагает фотографию или ручной ввод. Позиции с фотографии
сохраняются в текущий чек только после подтверждения пользователем.
Распределение расходов между участниками, сохранение компаний и платежи
пока не реализованы.

Распознавание бесплатное и локальное: системный **Tesseract OCR**, `pytesseract`
и Pillow/OpenCV. Языки — **rus+eng**. PaddleOCR, PaddlePaddle, OpenAI SDK,
`OPENAI_API_KEY` и внешние AI API не нужны. Во время обработки чека модели
и языковые данные не скачиваются. Сеть нужна боту только для Telegram API.

## Установка и запуск

Используются Python 3.12 и aiogram 3.x. В Debian/Ubuntu сначала выполните
однократную подготовку среды из корня проекта:

```bash
sh scripts/install_tesseract.sh
```

Скрипт запускает через root/sudo `apt-get update` и устанавливает системные пакеты
`tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng`, затем проверяет языки.
Если sudo отсутствует, запустите скрипт от root или попросите администратора
подготовить среду. Бот никогда не вызывает установку пакетов.
При установке нужен доступ к репозиторию пакетов; сетевые настройки скрипт
не меняет. Данные языков устанавливаются заранее вместе с пакетами.

Проверка установки:

```bash
tesseract --version
tesseract --list-langs
```

В списке должны быть **оба** языка: `rus` и `eng`. Одного `pip install pytesseract`
недостаточно: это Python-обёртка, системный executable устанавливается отдельно.
В другой ОС установите локальный Tesseract с русскими и английскими данными
и добавьте `tesseract` в `PATH`.

Установите Python-зависимости:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В Windows можно использовать `py -3.12 -m venv .venv`,
`.venv\Scripts\Activate.ps1` и `Copy-Item .env.example .env`.

Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot`.
Заполните в `.env` токен и запустите:

```dotenv
BOT_TOKEN=ваш_токен_от_BotFather
RECEIPT_OCR_BACKEND=tesseract
```

```bash
python -m bot
```

`.env` исключён из Git. Уже заданные переменные окружения имеют приоритет.
`RECEIPT_OCR_BACKEND` можно не задавать: `tesseract` используется по умолчанию.
Старые значения `paddleocr` и `openai` больше не поддерживаются; при обновлении
удалите их из настроек или замените на `tesseract`.
При нестандартном расположении заранее установленных языков можно задать
`TESSDATA_PREFIX` в окружении или `.env`: путь к каталогу с `rus.traineddata`
и `eng.traineddata`. Он должен содержать оба файла. Данные автоматически
не загружаются ни при запуске бота, ни при распознавании.

Откройте бота в Telegram и отправьте `/start`. Для остановки нажмите `Ctrl+C`.
Нужен доступ к `api.telegram.org`. Запускайте один экземпляр long polling
с одним токеном; у бота не должен быть активен webhook.

## Распознавание фотографии чека

Ресторанные чеки с гостями поддерживают подытоги гостей, полную сумму,
предоплату и остаток к оплате. Гость, стол, заказ, официант, заголовки таблицы
и платёжные строки не считаются товарами. Позиции сохраняют номер гостя.
Товары сравниваются с полной суммой; отдельно проверяются сумма подытогов
гостей и равенство «полная сумма − предоплата = к оплате».
Повреждённые итоговые числа не восстанавливаются догадками. Сомнительные
позиции пропускаются с предупреждением; сырой OCR-текст остаётся доступен.

Архитектура: **фото → подготовка Pillow → Tesseract → receipt parser → проверка
и подтверждение пользователем**.

Бот скачивает наибольший вариант Telegram-фотографии в `BytesIO`. Допускаются
файлы до 10 МиБ и изображения до 25 мегапикселей. Подготовка учитывает поворот
по EXIF, ищет границы светлой бумаги и при уверенном обнаружении обрезает фон
и выравнивает перспективу. При неопределённых границах сохраняется весь кадр.
Небольшой наклон исправляется по горизонтальным проекциям без обрезки краёв.
Grayscale увеличивается в 2–3 раза с пределом 3600 пикселей по длинной стороне;
применяются выравнивание теней, мягкий CLAHE-контраст, лёгкое удаление шума
и sharpening. Эрозия букв не используется. Уверенный результат Tesseract OSD
позволяет исправить поворот на 90/180/270°; при недоступном `osd` или недостатке
текста сохраняется ориентация по EXIF.

Сравниваются grayscale и adaptive Gaussian threshold с PSM **6, 4, 11**.
Grayscale остаётся отдельным кандидатом на случай потери тонких штрихов
при бинаризации. Оценка использует количество уверенных букв/цифр и целых
денежных значений; число разрозненных блоков PSM 11 не повышает оценку.
Такие блоки собираются в строки по координатам слов. Один `image_to_data`
возвращает текст и confidence каждого варианта. Язык — `rus+eng`, тайм-аут
до 12 секунд на конфигурацию, общий бюджет сравнения — 45 секунд, плюс до
5 секунд на OSD. Ошибка отдельного варианта не теряет успешные результаты.
Перед OCR проверяются executable и оба языка: отсутствие русского не приводит
к незаметному переходу на один английский. Распознавание выполняется в отдельном
рабочем потоке и не блокирует event loop бота.

До parser проверяются минимум три строки с уверенным текстом, шесть уверенных
слов/чисел и доля уверенных токенов. Слишком скудный или низкоуверенный текст
не превращается в позиции: бот предлагает переснять чек ближе, ровнее и без
теней. Сырой текст остаётся доступен по кнопке «📄 Показать распознанный текст».
Очень короткий чек тоже может потребовать ручного ввода. Выбранная обработка,
PSM, количество строк и оценка пишутся только в developer log; текст чека,
байты изображения и технические параметры в пользовательский ответ не попадают.

Существующий parser сохранён. Он поддерживает название с суммой справа,
количество × цену, колонки количество/цена/сумма и название на строке перед ценой.
Деньги разбираются и считаются через `Decimal`, без `float`; при сериализации
в FSM используются десятичные строки. Поддерживаются точка, запятая и пробелы
тысяч. Извлекаются название, количество, цена за единицу, сумма строки и итог
чека. Неизвестная цена за единицу остаётся `null`; если виден только итог строки,
количество предварительно считается равным одному.

Фискальные строки, дата/время, оплата, НДС и скидки отфильтровываются.
«ИТОГО» извлекается отдельно. Валюта по умолчанию RUB; обозначения USD/EUR
учитываются. Parser эвристический: сложная вёрстка и ошибки OCR могут дать
неполный список. Бот показывает найденные позиции, их сумму и итог чека,
если он найден, и предупреждает о расхождении сумм.

Кнопки проверки:

- «✅ Всё верно» — переносит позиции в текущий чек в FSM;
- «✏️ Исправить» — сохранённая заглушка редактирования позиций;
- «🔄 Распознать заново» — повторно скачивает последнюю фотографию и выполняет OCR;
- «📄 Показать распознанный текст» — показывает сырой текст без изменения чека;
- «❌ Отменить» — очищает состояние и возвращает стартовое меню.

Если OCR прочитал текст, но parser не выделил позиции, бот сразу показывает
сырой текст и предлагает ручной ввод, повторное распознавание или отмену.
Пустой результат, отсутствие Tesseract/языков и ошибки OCR также позволяют
отправить новое фото или перейти к ручному вводу. Внешнего fallback нет.

Фото вне сценария получает подсказку с кнопкой начала разделения чека.
Во время ручного ввода фотография не сбрасывает шаг и добавленные позиции.
Фото и распознанный текст не логируются. `pytesseract` использует временные файлы
на время вызова системного executable и удаляет их после обработки.
Постоянное хранение фото и база данных не используются.
В FSM до подтверждения остаются результат, сырой текст и Telegram-метаданные
фото. После подтверждения сырой текст и метаданные удаляются. Новый чек,
ручной ввод, отмена, `/start` и перезапуск очищают соответствующие данные.

## Диагностика OCR и запуска

При запуске бот пишет в developer log используемый Python, backend, версию
`pytesseract`, путь к Tesseract, `TESSDATA_PREFIX`, версию системного Tesseract
и доступные языки. Проверка выполняется в процессе бота после загрузки `.env`.
Если OCR не готов, в логе остаётся traceback; ручной ввод продолжает работать.

Ошибки распознавания записываются с полным traceback и исходной причиной,
включая сообщение/код ошибки Tesseract. Байты фотографии и полный OCR-текст
отдельно в лог не передаются. В Telegram пользователь получает понятное
сообщение и кнопки повтора, ручного ввода и отмены, без технических деталей.
Длинные traceback находятся в stderr процесса; сохраняйте его при запуске.

`TelegramConflictError: terminated by other getUpdates request` означает,
что тот же токен использует другой экземпляр long polling. Сначала остановите
предыдущий процесс (включая другие облачные задачи), затем запускайте новый.
Это ошибка получения обновлений Telegram, а не ошибка Tesseract.

При обновлении работающего экземпляра сверяйте checkout с `origin/main`:

```bash
git fetch origin main
git merge --ff-only origin/main
python -m pip install -r requirements.txt
python -m pip check
```

После проверки тестов остановите старый процесс и запустите бота заново
тем же Python, с теми же `BOT_TOKEN` и `TESSDATA_PREFIX`. Уже работающий Python
не подхватывает обновлённые модули автоматически. Установка Tesseract сама
по себе не меняет backend старого checkout: версия `7156c5f` использует только
OpenAI и без `OPENAI_API_KEY` отвечает «Распознавание пока не настроено».
В актуальном checkout Tesseract используется по умолчанию; проверьте в логе
нового процесса `backend=tesseract` и наличие `rus` и `eng`.

## Ручной ввод чека

Нажмите «🧾 Разделить чек» → «✍️ Ввести вручную». Бот последовательно спросит
название позиции, цену в рублях и количество. Цена должна быть больше нуля;
поддерживаются целые числа и дробные числа с точкой или запятой.
Количество — целое число больше нуля. При ошибке бот повторяет текущий шаг.

После добавления бот показывает список позиций, стоимость каждой позиции
(цена × количество) и общую сумму. «➕ Добавить позицию» запускает следующий
ввод, «✅ Закончить ввод» показывает итог и завершает сценарий,
«❌ Отменить» очищает чек и возвращает стартовое меню. `/start` также сбрасывает
текущий ввод. Расчёты используют `Decimal` без ошибок округления `float`.

Чеки и состояние FSM хранятся в оперативной памяти отдельно для каждого
пользователя и чата. После завершения ручного ввода, отмены или перезапуска
бота они очищаются. Подтверждённый распознанный чек остаётся до нового чека,
отмены, `/start` или перезапуска.

## Структура

```text
bot/
    __main__.py                 # Запуск и long polling
    config.py                   # BOT_TOKEN из окружения и .env
    handlers.py                 # Telegram-сценарии и FSM
    receipt.py                  # Существующий ручной ввод и точные суммы
    services/
        receipt_recognition.py  # Вход в локальный OCR
        tesseract_receipt_recognition.py # Выбор OCR-варианта, Tesseract rus+eng
        receipt_preprocessing.py # Обрезка/перспектива, Pillow/OpenCV, бинаризация
        receipt_models.py       # Модели, сырой текст и ошибки
        receipt_parser.py       # Существующий parser позиций и итогов
scripts/install_tesseract.sh    # Однократная системная установка Debian/Ubuntu
tests/
    test_config.py
    test_handlers.py
    test_receipt_recognition.py
    test_receipt_parser.py
    test_tesseract_receipt_recognition.py
    integration/test_tesseract_smoke.py
    integration/test_tilted_receipt_photo.py
```

## Тесты

Unit-тесты не запускают Tesseract и не требуют его установки. Подменяются
результат OCR, проверка языков и Telegram; настоящие Pillow/OpenCV проверяют подготовку
изображений. Сохранены тесты parser и сценарии ручного ввода. Дополнительно
проверяются отсутствие executable/языков, тайм-аут, сырой текст при ошибке parser,
подтверждение, повтор и отсутствие внешнего fallback.

```bash
python -m unittest discover -s tests -v
```

Отдельный integration/smoke-тест запускает настоящий Tesseract на синтетическом
PNG-чеке с русским и английским текстом через dispatcher и photo handler,
без `OPENAI_API_KEY` и явного выбора backend. Затем он проверяет состояние
проверки чека, текст ответа, позиции и `Decimal`-сумму:

```bash
python -m unittest discover -s tests/integration -v
```

Он пропускается, если Tesseract или `rus+eng` недоступны. Для кириллицы нужен
шрифт DejaVu Sans; при другом расположении задайте `TESSERACT_SMOKE_FONT`
путём к TTF со шрифтом, поддерживающим кириллицу.
Тесты не используют сеть, внешние OCR API или настоящие Telegram-токены.

Для дополнительного smoke test на настоящей фотографии с перспективой задайте
`RECEIPT_SMOKE_PHOTO` путём к `sample_images/receipt.jpg` из публичного проекта
[doc_scanner](https://github.com/andrewdcampbell/doc_scanner/blob/master/sample_images/receipt.jpg)
и повторите integration-команду. Тест проверяет обрезку/перспективу и текст
`BACON`, `FLOUR ALMOND`, `101.33` через обработчик фото с настоящим Tesseract.
Подменяется только Telegram-транспорт. Фотография не скачивается тестом
автоматически и не включена в репозиторий.
